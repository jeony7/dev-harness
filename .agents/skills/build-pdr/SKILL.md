# 요구사항 정리

메인은 프로젝트 요청과 전달받은 이해관계자 의견을 읽고 `docs/PDR.md`를 갱신한다. 작업 에이전트로 배정받았다면 지정한 조사 결과를 메인에게 반환한다.

- 문제·대상 사용자·현재 업무 흐름·성공 기준을 구체화한다. 출처가 있는 사실과 확인할 가정을 구분한다.
- REQ-001, AC-001-01처럼 안정적인 ID를 사용하고 P0/P1/P2와 관찰 가능한 Given/When/Then 기준을 적는다.
- 필요한 질문을 결정에 영향을 주는 순서로 정리한다. 업무 요구와 구현 아이디어를 구분하고 제외 범위를 명시한다.
- 실제 프로젝트에서 확인되지 않은 AI API·배포·운영 방식을 확정하지 않는다. 다른 어시스턴트의 대화가 자동 공유된다고 가정하지 않는다.
- 자료가 여러 묶음이고 독립 분석의 실익이 있으면 [에이전트 운영](../../../docs/SUBAGENTS.md)에 따라 조건·예외·근거 추출을 나눈다. 담당자는 조사 결과를 반환하고 메인이 충돌하는 해석을 대조해 PDR과 질문을 정리한다.
- AC를 변경하면 관련 `docs/REVIEW.md` 판정을 미검증으로 표시하고 변경 이유를 남긴다. 구현 착수는 현재 요청과 합의된 Step 범위를 따른다.
