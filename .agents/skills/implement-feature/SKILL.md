# 지정 Step 구현

현재 요청, `docs/ADR.md`의 해당 Step·계약, PDR의 관련 REQ/AC, 담당 코드·테스트와 필요한 스택 규칙부터 읽는다. 호출 관계·공유 타입 등 의존성을 따라 읽는 범위를 넓힌다.

작업 에이전트로 배정받았다면 지정한 수정·검증 범위만 수행하고 결과를 메인에게 반환한다. 공통 문서 갱신과 추가 위임은 메인이 담당한다.

- 단계가 미정이면 설계·분할안을 먼저 논의한다. 지정한 범위의 선행 조건을 확인하고 API·데이터 계약부터 핵심 사용자 흐름을 연결한다.
- 기존 프로젝트의 구조·기동 방식을 확인한다. 신규 앱은 실제 제공 환경과 코드 기본값에 맞춰 필요한 구성부터 만든다.
- 같은 Step의 작업량·독립성·조율 비용을 보고 직접 구현하거나 [에이전트 운영](../../../docs/SUBAGENTS.md)에 따라 필요한 부분만 위임한다. 메인이 서버·프론트 중 한쪽을 맡고 다른 쪽만 위임할 수 있다. 양쪽을 위임할 때는 각각 충분한 독립 작업이 있고 메인이 맡을 통합 작업이 있어야 한다. 메인은 API·상태 계약과 파일 담당 범위를 전달하고 담당자는 해당 스택 규칙을 적용해 결과를 보고한다.
- 메인은 공통 설정과 통합 준비를 진행한 뒤 담당자의 결과·변경 파일·검사 근거를 수집한다. API 계약 변경을 양쪽에 전달하고 실제 서버·화면 연결을 확인하며 오류를 수정·재검증한다. 임시 응답으로만 확인한 화면은 통합 완료로 판정하지 않는다.
- AI 출력의 ID·금액·권한 등은 서버에서 검증한다. 필요한 오류·빈 상태·중복·상태 변경을 처리한다.
- 기존 프로젝트의 검사 명령으로 변경한 동작을 검증한다. AGENTS.md의 기준에 맞는 기존 결과는 재사용하고, 영향 있는 검사와 미확인 통합 흐름을 실행한다. 실행한 검사와 재사용한 근거를 구분해 기록한다.
- 메인은 Step 결과·남은 문제를 ADR에, 관련 AC 판정·근거를 REVIEW에 기록한다. 다음 Step은 자동 착수하지 않으며 명시한 연속 진행 범위는 끝까지 수행한다.
