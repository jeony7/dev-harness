# 결과물 대조

현재 요청이 Step 리뷰인지 전체 리뷰인지 확인하고 해당 REQ/AC·Step, 변경 코드·관련 테스트, 기존 REVIEW의 검사 근거부터 읽는다. 영향이 확인되면 관련 코드·자료로 범위를 넓힌다.

작업 에이전트로 배정받았다면 지정한 검토·검증 결과를 메인에게 반환한다. 아래 REVIEW 갱신과 최종 판정은 메인이 담당한다.

- `docs/REVIEW.md`에 범위의 모든 AC를 빠짐없이 나열한다. 변경된 AC의 기존 판정은 재검증 전까지 미검증으로 표시한다.
- 독립 검토의 실익이 있으면 [에이전트 운영](../../../docs/SUBAGENTS.md)에 따라 AC 누락 대조와 경계·실패 사례 검토를 나눈다. 검토 범위와 실제 검사 담당을 지정하고, 담당자는 근거를 반환하며 REVIEW의 최종 편집·판정은 메인이 맡는다.
- 정상·실패·상태 전이와 UI 핵심 흐름의 실행 근거를 확인한다. AGENTS.md의 기준에 맞는 기존 근거는 재사용하고, 영향 있는 검사와 미확인 흐름은 실제로 검증한다. 코드 검사 성공만으로 기능 통과를 판정하지 않는다.
- 작업 에이전트의 부분 검사 결과와 최종 통합 검증을 구분한다. 대상 코드가 바뀐 뒤에는 영향 있는 결과를 재확인하고, 서버·프론트가 실제로 연결된 사용자 흐름을 기준으로 관련 AC를 판정한다.
- 각 AC에 통과/실패/차단/미검증과 실제 명령·관찰 결과·코드 위치 등 근거를 적는다. 실제 AI 호출과 모의를 구분한다. 관찰 결과와 재현 절차를 함께 남긴다.
- 발견한 문제를 수정하면 영향 있는 AC를 다시 확인한다. Step 완료는 해당 범위로, 전체 완료는 모든 P0와 미해결 차단 사항까지 확인한다.
- 문서 표시를 위해 기준을 완화하거나 미실행을 통과 처리하지 않는다. 남은 오류·미구현·미검증을 보고한다.
- 사용자가 제공한 실행 결과를 근거로 삼았다면 직접 관찰한 결과와 구분한다.
